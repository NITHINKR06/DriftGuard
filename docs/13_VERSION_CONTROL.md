## Git Large File Storage (LFS)

**File**: `.gitattributes`

DriftGuard uses **Git LFS** to efficiently manage large dataset and model files that exceed GitHub's 100MB file size limit.

### Configuration

```
data/**/*.csv filter=lfs diff=lfs merge=lfs -text
data/**/*.npy filter=lfs diff=lfs merge=lfs -text
```

### Why Git LFS?

✅ **Dataset Files**: CICIDS2017 and UNSW-NB15 CSVs exceed 100MB GitHub limit  
✅ **NumPy Arrays**: Model outputs (`.npy` files) are large binary files  
✅ **Version Control**: Need to track large file changes  
✅ **Collaboration**: Team members can pull large files efficiently  

### Files Tracked by LFS

- All CSV files in `data/` directory (~5GB total)
- All NumPy files (`.npy`) containing preprocessed data and model outputs
- Total LFS storage: ~5GB

### Setup Git LFS

```bash
# Install Git LFS (one-time setup)
git lfs install

# Track large file patterns (already configured in .gitattributes)
git lfs track "data/**/*.csv"
git lfs track "data/**/*.npy"

# Verify LFS tracking
git lfs ls-files

# Check LFS status
git lfs status

# Pull LFS files
git lfs pull
```

### Cloning Repository with LFS

```bash
# Clone with LFS files
git lfs clone https://github.com/NITHINKR06/DriftGuard.git

# Or clone normally then pull LFS
git clone https://github.com/NITHINKR06/DriftGuard.git
cd DriftGuard
git lfs pull
```

## Git Ignore Configuration

**File**: `.gitignore`

```
.venv/
src/__pycache__/
```

### Ignored Files

❌ **Virtual environment** (`.venv/`) - Platform-specific, should not be version controlled  
❌ **Python cache** (`__pycache__/`) - Auto-generated bytecode, not needed in repo  

### Intentionally Tracked Files

✅ **Jupyter notebook outputs** - For reproducibility and documentation  
✅ **Generated figures** - For research papers and presentations  
✅ **Model files** - Via Git LFS (`.pkl`, `.keras`)  
✅ **Data files** - Via Git LFS (`.csv`, `.npy`)  

### Adding More Ignore Patterns

```bash
# Add to .gitignore
echo "*.log" >> .gitignore
echo ".DS_Store" >> .gitignore
echo "*.tmp" >> .gitignore
```

```bash
# Install all at once
pip install -r requirements.txt

# Install specific category
pip install pandas numpy scipy  # Data processing only

# Upgrade all packages
pip install --upgrade -r requirements.txt

# Generate current environment
pip freeze > requirements_frozen.txt
```

### Dependency Management Best Practices

```bash
# Create requirements with exact versions
pip freeze > requirements_locked.txt

# Install from locked requirements
pip install -r requirements_locked.txt

# Check for outdated packages
pip list --outdated

# Update specific package
pip install --upgrade tensorflow
```


## Project Configuration Files

### Python Configuration

**File**: `pyproject.toml` (optional, for modern Python projects)

```toml
[build-system]
requires = ["setuptools>=61.0"]
build-backend = "setuptools.build_meta"

[project]
name = "driftguard"
version = "1.0.0"
description = "Cross-dataset network intrusion detection with ensemble ML"
requires-python = ">=3.10"
dependencies = [
    "pandas>=2.0.0",
    "numpy>=1.24.0",
    "scikit-learn>=1.3.0",
    # ... other dependencies
]

[tool.black]
line-length = 88
target-version = ['py310']

[tool.pytest.ini_options]
testpaths = ["tests"]
python_files = ["test_*.py"]
```

### Code Formatting (Black)

```bash
# Format all Python files
black src/ dashboard/

# Check without modifying
black --check src/

# Format specific file
black src/risk_scoring.py
```

### Linting (Flake8)

```bash
# Lint all Python files
flake8 src/ dashboard/

# Custom configuration
flake8 --max-line-length=88 --ignore=E203,W503 src/
```

## Collaboration Workflow

### Branching Strategy

```bash
# Create feature branch
git checkout -b feature/add-new-model

# Make changes and commit
git add src/train_new_model.py
git commit -m "Add new anomaly detection model"

# Push to remote
git push origin feature/add-new-model

# Create pull request on GitHub
```

### Commit Message Conventions

```bash
# Good commit messages
git commit -m "feat: Add SHAP explainability to dashboard"
git commit -m "fix: Resolve memory leak in LSTM training"
git commit -m "docs: Update deployment guide with Docker instructions"
git commit -m "refactor: Simplify risk scoring logic"
git commit -m "test: Add unit tests for data loader"

# Bad commit messages (avoid)
git commit -m "update"
git commit -m "fix bug"
git commit -m "changes"
```

## Continuous Integration (Future)

### GitHub Actions Example

```yaml
# .github/workflows/ci.yml
name: CI

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Set up Python
        uses: actions/setup-python@v2
        with:
          python-version: '3.10'
      - name: Install dependencies
        run: pipinstall -r requirements.txt
      - name: Run linting
        run: flake8 src/
      - name: Run tests
        run: pytest tests/
```
